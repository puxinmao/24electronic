# K230—水管步进电机控制：上机与调参

## 本版控制逻辑

`empty.c` 不再把每一个 K230 视觉帧转换成一次“短时间转动 → 停止 → 等下一帧”的脉冲。
这种频繁启停会造成电机顿挫，也会在图像帧率不稳定时让 PID 表现很差。

当前版本的流程是：

1. UART1 中断接收 K230 的 `$BALL,x,y,score` 数据；
2. 每一帧只更新**目标转速**，并对位置和速度做低通滤波；
3. 主循环以 1 ms 节拍对转速做斜坡限制；
4. 仅每 20 ms（或心跳 100 ms）发送一次 CAN 转速命令；
5. 反向时先平滑减速至零、等待 20 ms，再向反方向加速；
6. 丢失目标超过 250 ms 时，自动平滑停机。

因此，先把电机运动本身调顺，再调视觉 PD。

## 保留的引脚配置

- K230 串口：`UART1`，`PA9 = RX`、`PA8 = TX`，115200 baud。
- 电机 CAN：`CANFD0`，`PA13 = CAN_RX`、`PA12 = CAN_TX`。
- 按键：`PB21`（低有效）。按一下启动一次“中心 → +5 cm → -5 cm → 中心”的视觉闭环往返。
- LED：`PA2`。LED 亮表示单次往返正在执行。

程序上电后默认处于**居中平衡模式**：只要 K230 持续输出有效数据，系统就会尝试把小球保持在图像中心。PB21 不再是总使能开关；往返完成、K230 报无球、置信度不足，或有效视觉数据中断超过 250 ms 后，程序会回到（或保持在）普通居中平衡模式。

## 第一次上机

1. 先让水管处于安全行程中间，确保 CAN 收发器和电机供电正常。
2. 确认 LED 熄灭（普通居中平衡模式）；如需验证往返，再按 PB21 使 LED 点亮。
3. 在 K230 端发送一个低频的测试帧：
   - `$BALL,250,180,100\r\n`：按当前代码应该“抬高水管”；
   - `$BALL,390,180,100\r\n`：按当前代码应该“降低水管”。
4. 若两个方向相反，只交换 `empty.c` 内的方向定义含义（或交换两个值）：
   ```c
   #define ZDT_DIRECTION_RIGHT_RAISE  (0x01U)
   #define ZDT_DIRECTION_LEFT_LOWER  (0x00U)
   ```
   不要先改 PID 的正负号。
5. 发送 `$BALL,-1,-1,0\r\n`，或停止发送数据超过 250 ms，确认电机可以停下。

## 推荐调参顺序

所有参数都在 `empty.c` 的 **Tuning** 区域。

1. **先调平滑性**：从 `MAX_SPEED_RPM = 40`、`SPEED_SLEW_RPM_PER_SEC = 100` 开始；确认不丢步后再逐步增加。
2. **只调 P**：先将 `KD_RPM_PER_PX_PER_SEC_X100` 改为 `0`，逐步增大 `KP_RPM_PER_PIXEL_X100`，直到水管能及时把球拉回中心、但还没有明显来回摆动。
3. **再加入 D**：逐步增加 `KD_RPM_PER_PX_PER_SEC_X100`，只用来压制接近中心时的过冲；D 太大会因检测抖动而反复反向。
4. **最后调死区**：若中心附近频繁微动，增大 `POSITION_DEADBAND_PX`（例如 8 → 12）；若稳态偏差太大则减小它。
5. 若低速不动，增加 `MIN_MOVING_SPEED_RPM`；若低速太冲，则检查机械摩擦、驱动器细分和电机电流，不能只靠降低 PID。

## 与原程序相比的关键区别

原参考工程在每帧使用约 10–45 ms 的转动脉冲，脉冲结束后立即发送停止帧；CAN 发送还带同步等待。新的程序不在视觉帧处理中阻塞等待 CAN，也不根据每帧直接停电机，所以不会把相机帧率的抖动直接传递为电机启停。
